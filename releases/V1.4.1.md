## Objet

V1.4.1 formalise comme correctif de maintenance l’incrément
[ACCESS-002-07](../project-book/administration/ACCESS-002-07.md), intégré dans
les deux branches `develop`. Le correctif rend attribuables depuis
l’interface normale les capacités Configuration et Journaux déjà prises en
charge par le moteur d’autorisation.

Cette note prépare une publication future. Elle n’autorise ni fusion vers
`main`, ni tag, ni déploiement Apps Script, ni mutation de production.

## Périmètre applicatif

Le correctif fonctionnel porte exclusivement sur :

- `src/ui/admin/AccessAccounts.html` ;
- `src/ui/admin/AccessAccountsClient.html` ;
- `src/tests/access/Access002AdminUiTest.gs`.

La finalisation de version ajoute uniquement :

- `CHANGELOG.md` ;
- `README.md` ;
- `src/core/Core.gs` ;
- `src/core/VersionApi.gs` ;
- `src/tests/version/VersionTest.gs`.

La version embarquée devient `1.4.1`, avec le build `20260827.1` et le nom
« ACCESS et administration sécurisée — correctif d’attribution ».

## Quality Gate restant

Avant toute proposition de publication dans `main`, il faudra obtenir une
autorisation séparée pour :

1. synchroniser la tête exacte de la branche applicative dans la recette ;
2. vérifier la correspondance fichier par fichier ;
3. exécuter VERSION-001 ;
4. exécuter la suite ciblée ACCESS et la campagne cumulative ;
5. restaurer exactement la recette ;
6. consigner les SHA et résultats finaux dans le Project Book.

La fusion vers `main`, la création du tag `v1.4.1` et tout déploiement de
production constitueront ensuite des décisions séparées.
