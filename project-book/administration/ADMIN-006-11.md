## 3. Résultat de l’inventaire des propriétés

Les interfaces autorisées ne retournent pas les propriétés d’exécution Apps Script. Les valeurs ne doivent pas être ouvertes dans l’interface ou copiées dans un rapport pour tenter de contourner cette limite.

L’état est donc consigné sans hypothèse :

| Projet | Noms des clés | Empreintes |
|---|---|---|
| Portail RECETTE | non observables par les interfaces en lecture seule disponibles | non calculables sans accès contrôlé aux valeurs |
| Backend privé RECETTE | non observables par les interfaces en lecture seule disponibles | non calculables sans accès contrôlé aux valeurs |

Cette limite interdit l’installation tant qu’un mécanisme d’inspection explicitement autorisé ne garantit pas une sortie limitée aux noms et aux empreintes.

## 4. Propriétés contractuelles

Les seules propriétés du secret autorisées par ADMIN-006-08 sont :

- `AKS_PRIVATE_HMAC_CURRENT` ;
- `AKS_PRIVATE_HMAC_PREVIOUS`, uniquement pendant une rotation bornée ;
- `AKS_PRIVATE_SECRET_VERSION`.

Pour une première installation :

- `AKS_PRIVATE_HMAC_CURRENT` doit être identique sur le portail et le backend ;
- `AKS_PRIVATE_SECRET_VERSION` doit être identique sur les deux projets ;
- `AKS_PRIVATE_HMAC_PREVIOUS` doit rester absente ;
- toute clé contractuelle préexistante ou ambiguë provoque un arrêt fermé.

## 5. Inspecteur minimal requis

Avant D2, un inspecteur temporaire ou un mécanisme équivalent doit être autorisé séparément. Il doit :

1. s’exécuter localement sur chacun des deux projets ;
2. ne retourner que les noms des propriétés ;
3. calculer `SHA-256(UTF-8(valeur))` sans afficher la valeur ;
4. représenter une valeur absente par `[ABSENT]` ;
5. trier les clés de manière déterministe ;
6. refuser toute clé au préfixe `AKS_PRIVATE_` non prévue ;
7. ne produire aucune écriture, aucun journal contenant une valeur et aucune transmission distante ;
8. être retiré avec relecture exacte après le contrôle s’il nécessite un ajout temporaire de code.

La sortie attendue est limitée à :

`PROJECT_ROLE | PROPERTY_NAME | PRESENT | SHA256`.

## 6. Génération du futur secret

Après un précontrôle concluant et une nouvelle autorisation :

- générer au minimum 32 octets avec un générateur cryptographiquement sûr ;
- encoder la valeur en Base64URL sans remplissage ;
- ne jamais afficher la valeur dans la console, les journaux, le rapport ou Git ;
- calculer immédiatement son empreinte SHA-256 ;
- conserver uniquement l’empreinte dans le rapport ;
- utiliser un identifiant de version non secret, unique et horodaté ;
- maintenir le transport privé désactivé pendant toute l’installation.

Aucune valeur de secret ne doit être transmise dans le chat.

## 7. Sauvegarde préalable

Avant toute écriture, D2 doit produire pour chaque projet :

- la liste exacte des propriétés existantes ;
- leurs empreintes ;
- une sauvegarde locale protégée contenant les valeurs nécessaires au retour arrière ;
- une empreinte SHA-256 de la sauvegarde ;
- un contrôle empêchant l’écrasement d’une clé contractuelle inconnue.

La sauvegarde contenant des valeurs ne doit jamais être jointe au Project Book ni au rapport partageable.

## 8. Ordre d’installation initiale

Sous transport toujours désactivé :

1. vérifier de nouveau les identifiants exacts des deux projets ;
2. confirmer l’absence de collision ;
3. installer `AKS_PRIVATE_HMAC_CURRENT` et `AKS_PRIVATE_SECRET_VERSION` sur le backend ;
4. relire uniquement noms et empreintes ;
5. installer les mêmes propriétés sur le portail ;
6. relire uniquement noms et empreintes ;
7. comparer les empreintes croisées ;
8. confirmer l’absence de `AKS_PRIVATE_HMAC_PREVIOUS` ;
9. confirmer qu’aucun déploiement, endpoint ou transport n’a été créé ou activé.

L’opération échoue si les empreintes ne sont pas strictement identiques.

## 9. Retour arrière

Si un contrôle échoue :

1. maintenir le transport désactivé ;
2. restaurer le portail depuis sa sauvegarde protégée ;
3. relire noms et empreintes ;
4. restaurer le backend depuis sa sauvegarde protégée ;
5. relire noms et empreintes ;
6. supprimer uniquement les clés créées par D2 lorsqu’elles étaient initialement absentes ;
7. vérifier l’état final contre les empreintes préalables ;
8. conserver un rapport sans valeur secrète.

Le retour arrière ne doit toucher aucune propriété étrangère au préfixe contractuel.

## 10. Barrières avant installation

D2 ne peut être exécuté que si :

- l’inspecteur minimal est explicitement autorisé ;
- les deux projets sont identifiés sans ambiguïté ;
- les propriétés préexistantes sont connues par noms et empreintes ;
- aucune collision contractuelle n’existe ;
- la sauvegarde protégée et sa restauration ont un chemin défini ;
- le générateur cryptographique est disponible ;
- le transport demeure inactif ;
- aucune sortie ne peut révéler le secret.

## 11. Décision du précontrôle

Le protocole D2 est prêt, mais l’installation reste interdite.

La prochaine étape doit autoriser séparément l’inspection temporaire et réversible des propriétés, avec sortie limitée aux noms et empreintes. L’autorisation d’inspection ne devra pas autoriser simultanément la génération ou l’installation du secret.
