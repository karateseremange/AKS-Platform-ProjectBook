## 5. Périmètre fermé de D2-B

D2-B installe exclusivement les deux propriétés suivantes sur le backend puis sur le portail :

- `AKS_PRIVATE_HMAC_CURRENT` ;
- `AKS_PRIVATE_SECRET_VERSION`.

`AKS_PRIVATE_HMAC_PREVIOUS` doit rester absente : il s'agit d'une première installation, pas d'une rotation.

Sont explicitement reportés à D3 ou D4 :

- activation du backend ou du transport ;
- URL ou identifiant de déploiement backend ;
- identifiant du support LOG ;
- réglages anti-rejeu ;
- création de code backend ;
- version ou déploiement Apps Script ;
- raccordement du portail ;
- habilitation `LOG_READ`.

## 6. Précontrôles D2-B

L'opération s'arrête avant toute génération si l'un des contrôles échoue :

1. les Script ID ne correspondent pas exactement aux identifiants consignés ;
2. les HEAD ne correspondent pas aux états restaurés de D2-A ;
3. une clé `AKS_PRIVATE_` est déjà présente sur l'un des projets ;
4. les six propriétés historiques du portail ne correspondent plus à leurs empreintes D2-A ;
5. le backend ne contient plus zéro propriété ;
6. un inspecteur ou installateur temporaire existe déjà ;
7. le générateur cryptographique ou SHA-256 est indisponible ;
8. les chemins de restauration ne sont pas déterministes ;
9. une commande de version, déploiement, partage ou ACCESS est détectée.

Le contrôle compare les propriétés par noms et empreintes seulement. Aucune valeur préexistante ne doit être affichée.

## 7. Génération du secret

Après succès intégral des précontrôles :

- générer 32 octets au minimum avec un générateur cryptographiquement sûr ;
- encoder en Base64URL sans remplissage ;
- conserver la valeur uniquement en mémoire pendant l'installation ;
- calculer `SHA-256(UTF-8(secret encodé))` ;
- ne jamais écrire le secret dans la console, les journaux, le rapport, Git, le chat ou un fichier temporaire ;
- produire un identifiant de version non secret, unique et borné à RECETTE ;
- ne consigner que l'identifiant de version et l'empreinte du secret.

Toute exception avant la fin de l'installation provoque le retour arrière des seules clés créées.

## 8. Ordre d'installation

Le transport reste désactivé pendant toute l'opération.

1. sauvegarder les inventaires D2-A de référence ;
2. générer le secret et son identifiant de version ;
3. installer les deux propriétés sur le backend ;
4. relire le backend par noms et empreintes ;
5. confirmer deux propriétés exactement, même version attendue et absence de `AKS_PRIVATE_HMAC_PREVIOUS` ;
6. installer les deux mêmes propriétés sur le portail sans toucher aux six propriétés existantes ;
7. relire le portail par noms et empreintes ;
8. vérifier l'égalité stricte des empreintes HMAC entre portail et backend ;
9. vérifier l'égalité de la version par empreinte et par identifiant non secret ;
10. retirer manuellement tout code temporaire sur chaque projet ;
11. relire intégralement les deux HEAD et vérifier leur identité avec les sauvegardes de code ;
12. confirmer l'absence de version, déploiement, partage, activation et droit ACCESS.

Un installateur temporaire ne doit jamais être considéré comme supprimé par un simple `clasp push`. Sa suppression doit être visible, puis certifiée par relecture.

## 10. Retour arrière D2-B

Les deux clés contractuelles étant absentes avant D2-B, le retour arrière n'a pas besoin de recopier une valeur antérieure. Il doit :

1. maintenir le transport désactivé ;
2. supprimer uniquement `AKS_PRIVATE_HMAC_CURRENT` et `AKS_PRIVATE_SECRET_VERSION` du portail si elles ont été créées ;
3. vérifier le retour exact aux six propriétés D2-A du portail ;
4. supprimer uniquement ces deux clés du backend si elles ont été créées ;
5. vérifier le retour exact à zéro propriété backend ;
6. supprimer manuellement tout installateur temporaire ;
7. relire et comparer les HEAD de code aux sauvegardes ;
8. produire un rapport sans secret.

Les six propriétés ACCESS/AUDIT du portail ne doivent jamais être modifiées. Toute restauration partielle est un échec.
