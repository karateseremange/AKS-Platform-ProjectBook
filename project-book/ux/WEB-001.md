---

# 1. Objet

WEB-001 cadre la création d’un point d’accès clair à AKS Platform depuis le site WordPress de l’Association Karaté Serémange.

Le besoin est de rendre accessibles le Questionnaire santé, l’administration et les futurs services depuis une navigation cohérente, sans développer prématurément un portail spécifique.

---

# 2. Décision de positionnement

WEB-001 est planifié :

1. après la publication officielle d’AKS Platform V1.1 sur `main` ;
2. avant le démarrage du développement d’AKS Analytics ;
3. avant AKS Calendar.

Cette décision n’ajoute aucune fonctionnalité à la V1.1 stabilisée et ne retarde pas sa publication. Elle garantit que le point d’accès au produit sera traité avant l’arrivée des nouveaux modules métier.

---

# 3. Nom et organisation recommandés

Le libellé public recommandé est **« Services en ligne »**, plus compréhensible pour les familles que le nom technique « AKS Platform ».

La structure cible initiale est :

- **Questionnaire santé** — accès public ;
- **Administration AKS** — accès réservé ;
- futurs services publics ou réservés, ajoutés uniquement après leur publication.

Le nom « AKS Platform » reste le nom du produit et peut être utilisé dans les pages d’administration ou la documentation technique.

---

# 4. Principes d’accès

## 4.1 Accès public

Le Questionnaire santé des mineurs reste accessible :

- sans compte WordPress ;
- sans compte Google ;
- depuis le site public du club ;
- sur ordinateur et mobile.

Les futurs services publics ne sont ajoutés au menu qu’après leur mise en production.

## 4.2 Accès réservé

L’entrée **« Administration AKS »** dirige vers le Web App administratif distinct.

L’accès administratif conserve :

- l’authentification déléguée à Google ;
- l’autorisation minimale contrôlée côté serveur ;
- le principe du moindre privilège ;
- un refus explicite pour les personnes non autorisées ;
- une séparation complète avec le Web App public.

Le menu WordPress ne constitue pas un mécanisme de sécurité. Il fournit uniquement un point d’entrée ; les contrôles serveur restent obligatoires.

---

# 5. Périmètre du premier incrément

Le premier incrément comprend :

- la création ou l’adaptation du menu WordPress ;
- l’ajout des liens vers les services réellement publiés ;
- la séparation compréhensible entre accès public et accès réservé ;
- la vérification des parcours sur ordinateur et mobile ;
- la documentation de la procédure de maintenance des liens.

---

# 6. Exclusions

Le premier incrément ne comprend pas :

- un portail applicatif dédié ;
- un système de comptes ou de rôles WordPress ;
- une authentification développée par AKS Platform ;
- la fusion du Web App public et du Web App administratif ;
- la modification fonctionnelle du Questionnaire santé ;
- le développement d’AKS Analytics ou d’AKS Calendar ;
- l’affichage de données ou de modules simulés ;
- des liens vers des services non encore publiés.

---

# 7. Critères d’acceptation

WEB-001 sera validé lorsque :

- le menu **« Services en ligne »** est visible et compréhensible ;
- le Questionnaire santé est accessible depuis le parcours public ;
- l’administration est clairement présentée comme réservée ;
- l’entrée administrative cible le Web App administratif distinct ;
- les contrôles d’accès côté serveur restent conformes ;
- aucun module futur n’est présenté comme disponible avant sa publication ;
- les parcours sont vérifiés sur ordinateur et mobile ;
- la maintenance des liens est documentée ;
- aucune régression du Questionnaire santé ni de l’administration n’est observée.

---

# 8. Dépendances

WEB-001 dépend notamment de :

- ROADMAP-001 ;
- ADMIN-001 et ADMIN-002 ;
- SECURITY-001 ;
- UX-001 ;
- du connecteur WordPress déjà publié ;
- des URL de production des Web Apps public et administratif.

---

# 9. Risques et mesures de maîtrise

| Risque | Mesure |
|---|---|
| Confusion entre accès public et administration | Libellés distincts et mention explicite « accès réservé » |
| Faux sentiment de sécurité lié au masquage d’un lien | Maintien obligatoire des contrôles d’autorisation côté serveur |
| Présentation prématurée d’un module futur | Publication des entrées uniquement lorsque le service est réellement disponible |
| Rupture d’un lien après redéploiement | Documentation et contrôle des URL de production |
| Navigation mobile insuffisante | Validation explicite sur mobile avant clôture |

---

# 10. Résultat attendu

Le site WordPress devient le point d’entrée compréhensible vers les services disponibles d’AKS Platform, tout en conservant la séparation technique et sécuritaire entre le Questionnaire santé public et l’administration réservée.

- aucune modification du code AKS Platform ni du connecteur WordPress n’a été nécessaire.

---

# 12. Maintenance des liens

La maintenance du menu s’effectue dans l’administration WordPress, dans le menu principal du site.

La structure publiée est :

- **Services en ligne** ;
  - **Questionnaire santé** — page WordPress publique, ouverture dans le même onglet ;
  - **Administration AKS — accès réservé** — URL du Web App administratif, ouverture dans un nouvel onglet.

Après toute modification d’URL ou de déploiement, les contrôles suivants doivent être rejoués :

1. affichage du menu sur ordinateur ;
2. affichage du menu sur mobile ;
3. accès public au Questionnaire santé ;
4. accès administratif avec un compte autorisé ;
5. refus d’accès avec un compte non autorisé.

Les futurs services ne doivent être ajoutés au menu qu’après leur publication effective.

---

# 13. Clôture

WEB-001 est fonctionnellement terminé et validé. Le site WordPress fournit désormais le point d’entrée attendu vers les services disponibles d’AKS Platform, avec une séparation explicite entre accès public et administration réservée.

Le prochain chantier de la roadmap est **AKS Analytics**.
